# Como o ecossistema se organiza

Apps de marca (Farm, Hering, Reserva…) consomem libs compartilhadas. App Plataforma evolui as libs; App Custom entrega no app da marca.

## Dependências (de cima para baixo)

```text
app_marca          ← App Custom · telas da marca
        ↓
azzas_app_commons  ← features · cubits · orquestração
        ↓
┌──────────┬──────────┬────────────────┬──────────┬──────────┐
│ azzas_core │ azzas_ui │ azzas_analytics │ checkout │ azzas_cms │
│ dados      │ design   │ eventos · CRM   │ login    │ Strapi    │
└──────────┴──────────┴────────────────┴──────────┴──────────┘
```

## Camadas dentro de uma feature

### Camada de apresentação (UI)

Fluxo típico no design system — feature cross-brand:

```text
Template → composition_components → core_components → Tokens
```

### Camada lógica (dados)

Fluxo típico no core / commons:

```text
Cubit → UseCase → Repository → Model
```

:::tip[Feature nova de plataforma]
Pode tocar várias libs (core, ui, commons, cms…). Por isso o refinamento quebra em **1 task por lib** — cada uma com owner e versão própria.
:::
